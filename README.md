# affine_transformations_projection
Вновь команда «Графические». Лабораторная работа №6. Аффинные преобразования в пространстве. Проецирование

## Фигура вращения (задание 2)

Модуль `revolution.py` строит фигуру вращения по образующей, оси (X, Y или Z) и
числу разбиений; угол шага = 360° / n. Вершины образующей поворачиваются
матрицами `rotation_x/y/z` из `transforms.py`, соседние кольца соединяются
гранями (четырёхугольники, у полюсов на оси — треугольники). Модель содержит
вершины и грани, поэтому сохраняется в OBJ и показывается в просмотрщике.

В `obj_viewer.py`: **Файл → Фигура вращения…** (`Ctrl+R`) или кнопка
«Фигура вращения…» на левой панели. В окне задаются точки образующей (по одной
в строке: `x y z`, `z` можно не писать), ось, число разбиений, при необходимости
замыкание образующей (тор). Есть заготовки: ваза, цилиндр, конус, сфера, тор,
песочные часы. «Построить» показывает модель; «Построить и сохранить в OBJ…»
дополнительно сохраняет файл. Сохранённую модель можно открыть через
**Файл → Открыть OBJ…**, после чего к ней применяются любые аффинные
преобразования (перемещение, поворот, масштаб, отражение, вращение вокруг прямой).

Без интерфейса:

```powershell
python revolution.py -a y -n 24 -o vase.obj --preset Ваза
python revolution.py -a z -n 12 -o my.obj --points "1 0; 1 2; 0.5 3"
```

## Загрузка и сохранение Wavefront OBJ

Отдельное приложение `obj_viewer.py` использует существующие геометрические
классы, матрицы преобразований и интерфейс. Дополнительные пакеты не нужны
(требуется Python с tkinter).

Запуск из каталога `affine_transformations_projection`:

```powershell
python obj_viewer.py
python obj_viewer.py "C:\Users\79515\Downloads\utah_teapot_lowpoly.obj"
```

- **Файл → Открыть OBJ…** (`Ctrl+O`) — загрузить и показать модель.
- **Файл → Сохранить OBJ как…** (`Ctrl+Shift+S`) — сохранить текущие координаты
  и грани после преобразований.
- Панель слева: перемещение, поворот, масштабирование, отражение и вращение
  вокруг оси через центр или произвольной прямой.
- ЛКМ с перетаскиванием вращает камеру, колесо меняет экранный масштаб.
- Слайдеры «Вектор обзора» задают азимут и наклон камеры; отображаемый в
  строке состояния вектор направлен от камеры к сцене.
- **Файл → Подобрать вид** (клавиша `F` при фокусе на холсте) показывает модель
  целиком, сохраняя её координаты. После большого перемещения или увеличения
  можно подобрать вид повторно.
- **Сбросить фигуру** возвращает исходную загруженную модель. Список
  многогранников позволяет выбрать фигуры лабораторной №6 и сохранить их в OBJ.

Поддерживаются `v`, `f`, многоугольные грани, положительные и отрицательные
индексы, ссылки вида `v/vt/vn` и `v//vn`. Импортируются геометрия и нормали
`vn` с независимыми индексами для углов граней. Текстуры и материалы
не импортируются; экспорт OBJ пока сохраняет только геометрию `v/f`.
Отрисовка использует программный Z-буфер.

## Отсечение нелицевых граней

Отсечение включено по умолчанию и выполняется до передачи модели в `render_scene`.
`zbuffer.py` выполняет растеризацию, проверку глубины и отрисовку рёбер.
На вход Z-буферу приложение передаёт
исходные вершины и только те грани, которые обращены к камере.

- Для каждой грани строится вектор нормали суммой векторных произведений двух
  векторов в плоскости её треугольных частей. Нормали ориентируются наружу:
  у замкнутой сетки используется знак ориентированного объёма, у открытой
  поверхности — направление относительно центра модели.
- В параллельной (аксонометрической) проекции используется постоянное
  направление на камеру `(0, 0, 1)` в координатах вида. В перспективной
  проекции направление вычисляется от центра каждой грани к точке камеры
  `(0, 0, d)`. Грань остаётся, если скалярное произведение внешней нормали
  и направления на камеру положительно.
- Азимут и наклон вектора обзора изменяются слайдерами; вращение камеры
  перетаскиванием мыши также синхронизирует эти значения. Смена проекции
  переключает параллельный и перспективный варианты.
- **Показать удалённые грани** рисует исключённые из рендеринга грани красным
  пунктиром поверх изображения. Это диагностическая накладка: подсвеченные
  грани не возвращаются в Z-буфер. В строке состояния отображается количество
  оставленных и отсечённых граней. **Показать нормали лицевых граней** выводит
  синие стрелки внешних нормалей выбранного объекта.
- Для проверки куб выберите в списке многогранников, а сферу загрузите через
  **Файл → Открыть OBJ…** из `examples/sphere.obj`. Можно также строить сферу
  через **Фигура вращения…**.

Сам алгоритм отсечения находится в `backface_culling.py` и не зависит от
Tkinter или Z-буфера.

Алгоритм реализован в `zbuffer.py` без сторонних библиотек и графического API:

1. На каждый кадр выделяются массив глубины (начальное значение `+∞`) и RGB-буфер.
2. Многоугольники разбиваются на треугольники; в перспективе треугольники
   обрезаются по ближней плоскости перед проецированием.
3. Для каждого покрытого пикселя в его центре интерполируется глубина.
   В параллельной проекции это `-z`, в перспективной — `-1 / (d - z)`.
   Обратная глубина линейна в экранных координатах; меньшее значение ближе.
4. Цвет и глубина обновляются только при прохождении проверки глубины.
   Z-буфер не сортирует грани и не выполняет отсечение по нормали; в OBJ-
   просмотрщике список граней предварительно фильтруется модулем
   `backface_culling.py`.
5. Рёбра многоугольников также проверяются по заполненному буферу глубины.
   Координатные оси рисуются поверх изображения как вспомогательная разметка.

Растеризация выполняется на CPU, поэтому большие модели и окна могут
отрисовываться медленнее. Грани OBJ должны быть простыми многоугольниками
без самопересечений; неплоские грани интерпретируются как набор треугольников.

Проверки из каталога `affine_transformations_projection`:

```powershell
python -m unittest -v test_backface_culling
python main.py
```

## Освещение — часть участника 1: нормали, Ламберт и Гуро

Для демонстрации из корня проекта:

```powershell
python affine_transformations_projection/camera_viewer.py
```

В режиме камеры шейдинг Гуро включён по умолчанию. Откройте через
**Файл → Открыть OBJ…** файл `examples/sphere.obj`: на сфере хорошо видны
плавные переходы освещения. Доступны все прежние преобразования модели,
вращение камеры и отсечение нелицевых граней. Для этой демонстрации рёбра
в режиме заливки скрыты. Старый `obj_viewer.py` сохраняет прежнюю плоскую
закраску; новый режим подключён к конвейеру `camera.render_camera`.

Что добавлено:

- `Polyhedron.vertex_normals()` возвращает единичные нормали в порядке
  вершин. Они вычисляются суммированием нормалей смежных граней с весом по
  площади. Это сглаживает всю сетку; группы сглаживания OBJ `s` не разбираются.
- `Polygon.corner_normals` хранит нормали углов грани из OBJ. Одна позиция
  может иметь разные `vn` на разных гранях без дублирования геометрии.
  `Polyhedron.face_vertex_normals(index)` возвращает эти нормали, а для
  отсутствующих `vn` подставляет вычисленные. Поэтому OBJ с заданными
  нормалями может сохранять резкие рёбра, а OBJ без них сглаживается.
- Загрузчик поддерживает `vn`, `v//vn`, `v/vt/vn`, положительные и
  отрицательные индексы, а также грани со смешанными ссылками. Некорректные
  нормали и индексы дают ошибку с номером строки.
- `Polyhedron.transform()` сбрасывает вычисленные нормали; при следующем
  обращении они пересчитываются. Импортированные нормали преобразуются
  матрицей `A⁻ᵀ` и нормализуются. При вырожденном масштабе выполняется
  переход к нормалям оставшейся геометрии. `copy()` сохраняет нормали,
  фильтрация нелицевых граней сохраняет усреднение по полной сетке.
- `lighting.lambert_color(position, normal, light_position, object_color,
  ambient=0.15, diffuse=0.85)` считает цвет вершины:
  `C = C_object * clamp(ambient + diffuse * max(0, N·L), 0, 1)`,
  где `L = normalize(light_position - position)`. Все векторы задаются
  в мировых координатах, RGB — в диапазоне `0..255`. Для чистого диффузного
  Ламберта передайте `ambient=0`, `diffuse=1`. Бликов и затухания нет.
- `ZBuffer.triangle_gouraud(p0, p1, p2, c0, c1, c2, owner=0,
  reciprocal_w=None)` интерполирует цвет в каждом видимом пикселе.
  Для треугольников используются барицентрические координаты (линейная
  интерполяция по рёбрам и строкам), а не билинейная интерполяция четырёх
  углов квадрата. В перспективе передаются `(1/w0, 1/w1, 1/w2)`:
  `C = Σ(λi * Ci / wi) / Σ(λi / wi)`. RGB округляется после интерполяции;
  глубина по-прежнему интерполируется линейно в экранных координатах.
- `camera.clip_polygon_varyings()` обрезает и геометрию, и атрибуты вершин
  по ближней/дальней плоскостям до деления на `w`, поэтому у камеры нет
  скачков цвета на вновь образовавшихся вершинах.

API для подключения UI участником 2 (без изменения растеризатора):

```python
result = render_camera(
    models, camera, width, height,
    filled=True, backface=True,
    shading="gouraud",             # также доступен прежний "flat"
    light_position=(4.0, 6.0, 8.0), # точка в мировых координатах
    object_color=(90, 170, 245),    # None — прежняя палитра объектов
    ambient=0.15, diffuse=0.85,
    draw_edges=False,
)
```

В Реализация задания участника 2 вынесена в отдельный модуль `phong_toon.py`.
`obj_viewer.py` импортирует из него `render_scene`, а базовый `zbuffer.py`
оставляет низкоуровневый Z-буфер и тонкие адаптеры совместимости. Таким образом,
алгоритм освещения не смешан с интерфейсом и базовой растеризацией.

`obj_viewer.py` предоставляет управление освещением и режимом закраски:

- «Плоский» — одна яркость на грань;
- «Гуро» — освещение вершин по Ламберту и интерполяция RGB в Z-буфере;
- «Туншейдинг» — попиксельная интерполяция нормалей (Phong), их нормализация
  на каждом пикселе и дискретизация `N·L` на четыре уровня яркости;
- «Текстура» — пункт интерфейса-заглушка: пока загрузчик OBJ не сохраняет
  UV-координаты `vt` и изображения материалов, показывается базовый цвет
  объекта с плоским освещением.

Положение точечного света задаётся в мировых координатах, а перед расчётом
освещения переводится в систему камеры. Цвет выбранного объекта задаётся
через стандартный выбор цвета Tkinter. В перспективе нормали и позиции для
Phong интерполируются с поправкой `1/w`; ближнее отсечение переносит нормали
в новые вершины тем же параметром интерполяции, что и координаты.

Основные функции модуля `phong_toon.py`:

- `normalize_vector(vector)` — безопасная нормализация 3D-вектора;
- `transform_normal_to_view(normal, to_view)` — поворот нормали в координаты вида
  без переноса;
- `toon_band(diffuse_factor, thresholds)` — выбор одной из четырёх ступеней;
- `phong_toon_color(position, normal, light_position, object_color, ...)` —
  вычисление цвета одной точки поверхности;
- `triangle_phong_toon(buffer, ...)` — попиксельная растеризация треугольника;
- `render_scene(...)` — сборка сцены, подготовка нормалей, обрезка,
  перспективная коррекция и выбор одного из режимов закраски.

API программного Z-буфера:

```python
buffer = render_scene(
    models, to_view, width, height, zoom, projection, distance,
    filled=True,
    shading="toon",                  # flat | gouraud | toon | texture
    light_position=(4.0, 6.0, 8.0),  # мировые координаты источника
    object_color=(90, 170, 245),
    ambient=0.15, diffuse=0.85,
)
```

`ZBuffer.triangle_phong_toon(p0, p1, p2, n0, n1, n2, light_position, ...)`
оставлен как совместимый метод-адаптер: он передаёт управление функции
`phong_toon.triangle_phong_toon(buffer, ...)`. Основная реализация теперь
расположена в отдельном файле. Функция принимает экранные точки, нормали
в соответствующих вершинах и связанные с ними 3D-позиции через
`positions=(p0_3d, p1_3d, p2_3d)`. Параметр
`reciprocal_w=(1/w0, 1/w1, 1/w2)` включает перспективно-корректную
интерполяцию. При ручном изменении координат вне `Polyhedron.transform()`
вызовите `recalculate_vertex_normals()`; импортированные нормали OBJ при этом
остаются приоритетными.
